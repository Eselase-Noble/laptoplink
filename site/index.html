Why it is different

Security first, then fast

No home-rolled cryptography, no data held in memory, and nothing trusted until it verifies. Speed came after the guarantees, not instead of them.

01

Encrypted & authenticated

A Noise XX handshake proves both machines by their keys, then ChaCha20-Poly1305 protects every byte. Identity is a key, never an IP address.

02

Verified byte for byte

Each chunk is BLAKE3-checked before it touches disk, and the whole file is checked again before it is committed with an atomic rename.

03

Resumable

If a transfer drops, run it again. The receiver asks only for the chunks it is still missing. Nothing that arrived is ever sent twice.

04

Flat memory

Everything streams. A one terabyte file uses the same memory as a one megabyte file, bounded no matter how large the transfer gets.

05

rsync-style sync

Keep a folder in sync, skipping what is already there. When a big file changed a little, delta transfer sends only the blocks that differ.

06

Safe by construction

Path traversal, absolute paths, and symlink tricks are refused. Deletion during sync is opt-in, confirmed, and only after transfers succeed.

Measured, not promised

Fast on a single core

On a 2019 i9 laptop, 512 MiB over loopback, encrypting and double-hashing every byte. Reproduce it with the benchmark script in the repo.

Up and running in a minute

Quickstart

Install the binary, start a listener on one machine, send from the other. The short command is laplink; laptoplink works too.

  1. curl -fsSL …/install.sh | bash

    Installs laplink for your OS, or build from source with cargo build --release.

  2. laplink receive --dest ~/incoming --accept-new

    On the receiving machine. It prints its address and fingerprint.

  3. laplink send ./bigfile.iso --to 192.168.1.50

    On the sending machine. Watch the live rate.

  4. laplink sync ./project --to 192.168.1.50 --delta

    Keep a folder in sync, sending only what changed.

No hand-waving

Trust, spelled out

Machines are identified by a cryptographic key, not an IP address, so nobody can impersonate a device you trust just by taking its address. The receiver turns away unknown machines by default. For the strongest guarantee you read the short fingerprint to each other over a channel you already trust, which defeats even a machine in the middle on the first connection.

Being honest: this is local-network software today. Transfers across the internet, NAT traversal, relays, and storing keys in the OS keystore are on the roadmap, not done. The threat model in the repo lists every limitation plainly.
