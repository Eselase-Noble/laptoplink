It works like rsync, feels like AirDrop, and trusts no one in between.

Encrypted, and it checks who's there

Every connection is a mutually authenticated handshake, then ChaCha20-Poly1305 on the wire. A machine is known by its key, not its address, so no one can pose as a computer you trust.

Nothing arrives corrupted

Each chunk is hashed with BLAKE3 before it hits the disk, and the whole file is checked again before it is put in place. A bad byte never becomes a saved file.

Pick up where it dropped

If the network cuts out, run it again. The far side asks only for the chunks it is still missing. Nothing that already arrived moves twice.

Terabytes without filling memory

Everything streams. A one terabyte file uses the same memory as a one megabyte file, so the size of the job never decides whether it runs.

Keep a folder in step

Sync skips files that already match, and when a large file changed only a little it sends just the parts that differ. A small edit in a big file moves in kilobytes.

Careful with your disk

It refuses paths that try to escape the folder you chose, never follows a surprise symlink, and only deletes during a sync when you ask and confirm.

One command on each machine.

The receiver listens; the sender connects straight to it. The bytes go device to device, checked the whole way, and land only once they verify.

Send and receive

Two machines, one command each. The receiver listens; the sender points at its address (the default port is 9031).

On the machine that will receive
$laplink receive --dest ~/incoming --accept-new

Starts listening and prints its fingerprint. --accept-new trusts the first device that connects; drop it once paired.

On the machine that will send
$laplink send ./movie.mkv --to 192.168.1.50

Send a file or a whole folder. Watch the live rate; the file lands verified on the other side.

Keep a folder in sync (only what changed)
$laplink sync ./photos --to 192.168.1.50 --delta

Skips files already there; with --delta, a large file that changed a little moves in kilobytes. Add --dry-run to preview, --delete to mirror.

Leave the receiver always on (no terminal to keep open)
$laplink agent start --accept-new --allow-sender-dest

Runs a background receiver that keeps listening after you close the terminal. Check it with agent status, stop it with agent stop. With it running and --allow-sender-dest, the other machine sends in one command and picks the folder: laplink send ./movie.mkv --to IP --dest ~/Movies.

All commands 
laplink device show                 show this machine's identity and fingerprint
laplink device pair --fingerprint FP   trust another machine by its fingerprint
laplink send PATH... --to ADDR      send files or folders  [--dest DIR]
laplink receive --dest DIR          listen for incoming transfers  [--accept-new --allow-sender-dest]
laplink sync SRC --to ADDR          one-way folder sync  [--dry-run --delete --delta --exclude GLOB]
laplink agent start | status | stop always-on background receiver
laplink transfer list | resume ID   list or continue interrupted transfers
laplink doctor                      check identity, port, and setup
